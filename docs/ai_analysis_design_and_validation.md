AI 감정분석 설계 및 프롬프트 검증

## 1. 문서 목적

본 문서는 리뷰 감정분석 모듈의 실제 구현 내용을 기준으로 다음 항목을 설명한다.

- 실제 AI 프롬프트 원문 및 감정 분류 기준
- confidence 설계 기준과 낮은 confidence 결과의 활용 방안
- 프롬프트 튜닝 과정 및 샘플 리뷰 기반 품질 검증 결과

본 프로젝트의 감정분석은 `src/ai_client.py`에서 수행하며, 프롬프트 버전별 비교가 가능하도록 `prompt_version`을 사용한다.

현재 최종 적용 프롬프트 버전은 `v3`이다.

---

# 2. 실제 AI 프롬프트 및 감정분류 설계

## 2.1 초기 프롬프트 v1

초기 감정분석 프롬프트는 다음과 같이 구성하였다.

System Prompt

```text
당신은 고객 리뷰 감정분석 도우미입니다.
요청된 출력 형식을 정확히 지켜주세요.
```

### User Prompt

```text
다음 고객 리뷰의 감정을 분석하세요.

리뷰:
{review_text}

반드시 아래 형식으로만 답하세요.

sentiment: positive 또는 neutral 또는 negative
confidence: 0.0부터 1.0 사이 숫자
```

v1은 출력 형식은 명확했지만 다음과 같은 한계가 있었다.

- positive, neutral, negative의 구체적인 판단 기준이 없음
- 긍정과 부정이 함께 존재하는 혼합형 리뷰의 판단 기준이 없음
- confidence가 감정 강도인지 분류 확신도인지 정의되어 있지 않음
- 모호하거나 정보가 부족한 리뷰에 대한 처리 기준이 없음

이 문제를 보완하기 위해 v2, v3 프롬프트를 순차적으로 설계하였다.

---

## 2.2 최종 프롬프트 v3의 감정분류 기준

현재 최종 적용 중인 v3에서는 감정분류 기준을 다음과 같이 명시하였다.

### Positive

리뷰 전체의 핵심 평가가 다음과 같은 경우 positive로 분류한다.

- 만족
- 추천
- 칭찬
- 긍정적인 사용 경험

### Negative

리뷰 전체의 핵심 평가가 다음과 같은 경우 negative로 분류한다.

- 불만
- 문제점
- 실망
- 개선 요구
- 부정적인 사용 경험

### Neutral

다음과 같은 경우 neutral로 분류한다.

- 사실 전달 중심인 리뷰
- 긍정과 부정이 함께 존재하여 어느 한쪽도 명확히 우세하지 않은 경우
- 평가 방향이 명확하지 않은 경우
- 정보가 부족하여 긍정 또는 부정으로 판단하기 어려운 경우

---

## 2.3 혼합형 리뷰 판단 기준

혼합형 리뷰에서는 단순히 특정 긍정·부정 단어의 존재만으로 감정을 결정하지 않도록 하였다.

예를 들어 다음과 같은 문장이 있을 수 있다.

```text
포장은 아쉬웠지만 제품 자체는 나쁘지 않았습니다.
```

이 경우 부정 표현인 `아쉬웠지만`과 약한 긍정 표현인 `나쁘지 않았습니다`가 함께 존재한다.

v3에서는 다음과 같은 판단 원칙을 적용하였다.

- 특정 단어 하나만 보고 분류하지 않는다.
- 리뷰 전체 의미와 최종 평가를 기준으로 판단한다.
- 어느 한쪽이 명확하게 우세한 경우에만 positive 또는 negative로 판단한다.
- 긍정과 부정의 비중이 비슷하면 neutral로 판단한다.
- `괜찮다`, `나쁘지 않다`, `조금 아쉽다`와 같은 약한 표현은 과도하게 해석하지 않는다.

---

# 3. Confidence 설계 기준

## 3.1 Confidence의 의미

본 프로젝트에서 confidence는 감정의 강도가 아니다.

confidence는 다음의 의미로 정의하였다.

> AI가 자신이 선택한 감정 분류 결과가 맞다고 판단하는 확신도

따라서 강한 긍정 또는 부정 표현이 포함되어 있다는 이유만으로 반드시 confidence가 높은 것은 아니다.

---

## 3.2 Confidence 부여 기준

다음과 같은 경우 높은 confidence를 부여할 수 있도록 프롬프트를 설계하였다.

- 긍정 또는 부정 방향이 매우 명확한 경우
- 리뷰의 평가 대상과 평가 방향이 명확한 경우
- neutral 판단의 근거가 명확한 경우

반대로 다음과 같은 경우 confidence를 낮추도록 하였다.

- 긍정과 부정이 혼재하는 경우
- 표현이 모호한 경우
- 판단에 필요한 정보가 부족한 경우
- 감정 방향이 명확하지 않은 경우
- mixed 또는 uncertain 유형의 리뷰

---

# 4. 낮은 Confidence 결과의 활용 방안

## 4.1 현재 구현 상태

현재 구현에서는 다음 기능까지 적용되어 있다.

- 감정분석 결과 저장
- confidence 값 저장
- 리뷰 조회 시 감정과 confidence 표시
- 모델명과 프롬프트 버전별 결과 저장
- 동일 리뷰에 대한 프롬프트 버전별 결과 비교

현재는 낮은 confidence 결과를 자동으로 재분석하는 기능까지는 구현하지 않았다.

따라서 낮은 confidence에 대한 자동 처리 정책은 향후 개선 방안으로 구분하였다.

---

## 4.2 향후 검수 기준 예시

향후 실제 운영 시 다음과 같은 기준을 적용할 수 있다.

| Confidence            | 활용 기준                       |
| --------------------- | ------------------------------- |
| 0.80 이상             | 일반 분석 결과로 활용           |
| 0.60 이상 ~ 0.80 미만 | 검토 후보                       |
| 0.60 미만             | 사람 검수 또는 재분석 우선 대상 |

위 기준값은 현재 코드에 고정되어 있지 않으며, 실제 운영 데이터와 품질 검증 결과를 기반으로 조정할 필요가 있다.

---

## 4.3 향후 개선 방안

낮은 confidence 결과에 대해서는 다음과 같은 개선이 가능하다.

- 낮은 confidence 리뷰만 재분석
- 다른 프롬프트 버전을 사용한 재검증
- 다른 모델을 사용한 교차검증
- 별점과 감정이 크게 다른 리뷰 우선 검수
- 혼합형 리뷰 별도 관리
- 사람 검수 결과를 다시 프롬프트 개선에 활용

이를 통해 모든 리뷰를 사람이 검수하는 대신, 판단이 어려운 리뷰에 검수 인력을 집중할 수 있다.

---

# 5. 프롬프트 튜닝 과정

## 5.1 검증 목적

단순히 프롬프트를 작성하는 것에 그치지 않고 실제 샘플 리뷰를 이용해 v1, v2, v3의 결과를 비교하였다.

검증 목적은 다음과 같다.

- 감정 분류 기준을 명문화했을 때 실제 결과가 어떻게 달라지는지 확인
- 혼합형 리뷰 처리 성능 확인
- confidence 값이 분류 결과와 일관되게 작동하는지 확인
- 프롬프트 수정 전후 결과를 비교하여 개선 방향 도출

---

## 5.2 검증 데이터 구성

별도의 검증용 CSV 파일을 생성하였다.

파일명:

```text
prompt_validation.csv
```

총 15개의 리뷰를 구성하였다.

- 명확한 positive 리뷰: 5건
- 명확한 negative 리뷰: 5건
- neutral / factual / mixed / uncertain 리뷰: 5건

각 리뷰에 대해 AI 분석 전에 사람이 먼저 `human_label`을 지정하였다.

이 방법을 사용한 이유는 AI 결과를 본 후 사람이 정답을 바꾸는 것을 방지하고, 동일한 기준으로 프롬프트 버전을 비교하기 위해서이다.

검증 시 사용한 일치율 계산 기준은 다음과 같다.

```text
라벨 일치율 = AI 감정 라벨과 사람 기준 라벨이 일치한 건수
             ÷ 정상 분석된 전체 검증 리뷰 수
             × 100
```

# 6. 프롬프트 버전별 검증 과정

## 6.1 v1

v1은 가장 단순한 초기 프롬프트이다.

특징은 다음과 같다.

- 감정 분류 기준 없음
- 혼합형 리뷰 처리 기준 없음
- confidence 의미 정의 없음
- 출력 형식만 지정

초기 비교 실험에서는 비교적 높은 일치율을 보였지만, mixed 리뷰를 어떤 기준으로 판단하는지 설명하기 어려웠다.

---

## 6.2 v2

v2에서는 다음 내용을 추가하였다.

- positive / neutral / negative 기준 명문화
- 리뷰 전체 의미를 기준으로 판단하도록 지시
- 혼합형 리뷰에서는 어느 평가가 핵심인지 판단하도록 지시
- confidence를 감정 강도가 아닌 분류 확신도로 정의

그러나 실제 검증 결과, 혼합형 리뷰에서 한쪽 감정을 지나치게 적극적으로 선택하는 문제가 나타났다.

또한 일부 오분류 결과에서도 confidence가 높게 나타났다.

즉 프롬프트를 더 상세하게 작성했다고 해서 반드시 품질이 향상되는 것은 아니라는 점이 확인되었다.

---

## 6.3 v3

v2 검증 결과를 바탕으로 v3에서는 다음 내용을 강화하였다.

- 긍정과 부정이 함께 존재하고 어느 한쪽도 명확히 우세하지 않으면 neutral 처리
- 어느 한쪽이 명확하게 강한 경우에만 positive 또는 negative로 분류
- `괜찮다`, `나쁘지 않다`, `조금 아쉽다`와 같은 약한 표현을 과도하게 해석하지 않도록 제한
- mixed 또는 uncertain 리뷰에서 confidence를 과도하게 높이지 않도록 지시

이를 통해 혼합형 리뷰의 판단 안정성을 높이는 방향으로 프롬프트를 수정하였다.

---

# 7. 검증 결과

동일한 15개의 리뷰에 대해 v1, v2, v3 프롬프트를 각각 적용하였다.

검증 프로그램:

```text
validate_prompts.py
```

검증 결과 파일:

```text
prompt_validation_results.csv
```

최종 비교 결과는 다음과 같다.

| 프롬프트 버전 | 성공 건수 | 사람 라벨 일치율 | 평균 Confidence |
| ------------- | --------: | ---------------: | --------------: |
| v1            |   15 / 15 |            93.3% |           0.935 |
| v2            |   15 / 15 |            80.0% |           0.970 |
| v3            |   15 / 15 |            93.3% |           0.920 |

---

# 8. 결과 해석

## 8.1 v2의 문제점

v2에서는 감정분류 기준을 구체적으로 추가하였지만 사람 라벨 일치율이 80.0%로 감소하였다.

특히 mixed 유형의 리뷰에서 오분류가 발생하였다.

또한 평균 confidence는 0.970으로 가장 높게 나타났다.

이는 다음과 같은 문제를 의미한다.

> 분류 결과의 사람 기준 일치율은 낮아졌지만 AI가 자신의 판단에 더 높은 확신을 부여하는 현상이 나타났다.

따라서 confidence 값이 높다는 이유만으로 분석 품질이 높다고 판단해서는 안 되며, 실제 라벨 일치 결과와 함께 해석할 필요가 있다.

---

## 8.2 v3 개선 효과

v3에서는 mixed 리뷰와 ambiguous 리뷰에 대한 판단 기준을 강화하였다.

그 결과 이번 검증 실행에서 라벨 일치율은 다음과 같이 개선되었다.

```text
v2 80.0%
↓
v3 93.3%
```

즉 13.3%p 개선되었다.

평균 confidence는 다음과 같이 변화하였다.

```text
v2 0.970
↓
v3 0.920
```

이는 혼합형 및 불확실 리뷰에서 과도하게 높은 confidence를 줄이려는 프롬프트 수정 방향과 일치한다.

---

# 9. 혼합형 리뷰 사례 분석

## 사례 1

```text
제품은 괜찮은데 가격이 조금 비싼 것 같습니다.
```

사람 기준 라벨:

```text
neutral
```

v2 결과:

```text
negative
```

v3 결과:

```text
neutral
```

v2에서는 가격에 대한 부정 표현을 중심으로 negative로 판단했지만, v3에서는 제품에 대한 긍정 요소와 가격에 대한 부정 요소가 함께 존재하는 mixed 리뷰로 판단하여 neutral로 분류하였다.

---

## 사례 2

```text
포장은 아쉬웠지만 제품 자체는 나쁘지 않았습니다.
```

사람 기준 라벨:

```text
neutral
```

v2 결과:

```text
positive
```

v3 결과:

```text
neutral
```

v3에서는 `아쉽다`, `나쁘지 않다`와 같은 약한 표현을 한쪽 감정으로 과도하게 해석하지 않도록 기준을 보완하였다.

또한 v3에서 이 리뷰의 confidence가 0.80으로 나타나, 혼합형 리뷰에서 과도한 확신을 줄이려는 프롬프트 수정 방향도 확인할 수 있었다.

---

## 사례 3

```text
배송은 빨랐지만 제품 품질은 기대 이하였습니다.
```

사람 기준 라벨:

```text
neutral
```

v3 결과:

```text
negative
```

이 사례는 사람 기준과 AI 결과가 일치하지 않았다.

그러나 `배송은 빨랐다`는 긍정 평가와 `제품 품질은 기대 이하`라는 부정 평가가 함께 존재하며, 제품 자체의 품질을 핵심 평가로 보면 negative로 해석할 가능성도 있다.

따라서 이 사례의 human_label은 절대적인 정답이라기보다 본 프로젝트에서 설정한 검증 기준으로 보았다.

이 한 사례에 맞추기 위해 추가로 프롬프트를 수정할 경우 특정 검증 데이터에 과도하게 맞춰질 가능성이 있다고 판단하여 추가 튜닝은 수행하지 않았다.

---

# 10. 최종 프롬프트 채택

검증 결과를 바탕으로 현재 프로젝트에서는 `v3`를 최종 프롬프트로 사용한다.

현재 `config.json`의 설정은 다음과 같다.

```json
"prompt_version": "v3"
```

실제 DB에서도 동일한 리뷰에 대해 모델 및 프롬프트 버전별 분석 결과가 별도로 저장되는 것을 확인하였다.

예를 들어 리뷰 ID 1에는 다음과 같은 분석 이력이 존재한다.

```text
gpt-4o-mini / v1 / positive / confidence 0.95
gpt-5-mini  / v1 / positive / confidence 0.95
gpt-5-mini  / v2 / positive / confidence 1.00
gpt-5-mini  / v3 / positive / confidence 0.95
```

따라서 프롬프트 변경 전후의 분석 결과를 비교하고 버전별 분석 이력을 관리할 수 있다.

---

# 11. 검증 결과 해석 시 주의사항

본 검증 결과의 `라벨 일치율`은 15개의 소규모 검증 샘플에서 사람이 사전에 지정한 라벨과 AI 결과가 일치한 비율이다.

따라서 이를 일반적인 모델 정확도(accuracy)라고 단정하지 않고, 본 프로젝트의 프롬프트 비교를 위한 **샘플 라벨 일치율**로 해석하였다.

또한 동일한 v1 프롬프트를 반복 실행했을 때 첫 번째 실험에서는 86.7%, 이후 실험에서는 93.3%의 라벨 일치율이 나타났다.

이는 LLM의 응답이 실행마다 일부 달라질 수 있음을 보여준다.

따라서 이번 결과만으로 v3가 모든 리뷰에서 v1보다 우수하다고 단정하지 않았다.

이번 검증에서 확인한 핵심은 다음과 같다.

- v2에서 mixed 리뷰의 과도한 극성 분류 문제가 확인됨
- 해당 실패 사례를 분석하여 v3의 판단 규칙을 수정함
- v3에서 v2 대비 mixed 리뷰의 라벨 일치가 개선됨
- v2에서 나타난 높은 confidence 경향도 v3에서 완화됨

# 12. 향후 품질 검증 개선 방안

현재 검증은 15건의 소규모 샘플을 이용한 1차 실험이다.

향후에는 다음과 같은 방식으로 검증을 확대할 수 있다.

- 검증 리뷰 수 확대
- positive / neutral / negative별 샘플 수 확대
- mixed 및 uncertain 리뷰 추가
- 동일 프롬프트 반복 실행을 통한 결과 변동성 확인
- 감정별 Precision, Recall, F1-score 측정
- Confusion Matrix를 이용한 오분류 유형 분석
- 2명 이상의 사람이 독립적으로 라벨링하여 사람 간 라벨 일치도 확인
- 낮은 confidence 결과와 실제 오분류의 관계 분석

이를 통해 단순 라벨 일치율뿐만 아니라 감정별 성능과 프롬프트의 안정성을 보다 체계적으로 평가할 수 있다.

# 13. 관련 구현 및 검증 파일

본 문서와 관련된 주요 파일은 다음과 같다.

```text
src/ai_client.py
src/analyzer.py
config.json
validate_prompts.py
prompt_validation.csv
prompt_validation_results.csv
prompt_validation_results_v1_v2.csv
```

각 파일의 역할은 다음과 같다.

- `src/ai_client.py`: AI 호출 및 버전별 감정분석 프롬프트 구현
- `src/analyzer.py`: AI 분석과 DB 저장 기능 연결
- `config.json`: AI 모델 및 현재 적용할 prompt_version 설정
- `validate_prompts.py`: 동일 검증 데이터에 여러 프롬프트를 적용하는 비교 검증 프로그램
- `prompt_validation.csv`: 사람이 AI 분석 전에 라벨을 지정한 검증용 리뷰
- `prompt_validation_results.csv`: v1, v2, v3 비교 검증 결과
- `prompt_validation_results_v1_v2.csv`: 초기 v1, v2 비교 결과 백업

# 14. 결론

본 프로젝트에서는 LLM API를 단순 호출하는 것에 그치지 않고 다음과 같은 품질 개선 과정을 수행하였다.

```text
초기 프롬프트 설계
        ↓
사전 라벨링된 샘플 리뷰 검증
        ↓
오분류 사례 분석
        ↓
프롬프트 수정
        ↓
동일 샘플 재검증
        ↓
최종 프롬프트 v3 채택
```

v1에서 시작하여 감정분류 기준과 confidence 기준을 구체화한 v2를 설계하였으나, 실제 검증 과정에서 mixed 리뷰를 한쪽 감정으로 과도하게 분류하고 높은 confidence를 부여하는 문제가 확인되었다.

이에 v3에서는 neutral 판단 기준과 mixed/uncertain 리뷰의 confidence 기준을 보완하였다.

이번 검증 실행에서 v2의 사람 라벨 일치율 80.0%가 v3에서 93.3%로 개선되었으며, 평균 confidence는 0.970에서 0.920으로 조정되었다.

다만 15건의 소규모 검증이며 LLM 응답의 변동성도 확인되었으므로 이를 일반적인 모델 정확도로 단정하지 않았다.

이번 작업을 통해 프롬프트 설계, 실제 샘플 검증, 실패 사례 분석, 프롬프트 튜닝, 버전 관리로 이어지는 AI 감정분석 품질 개선 과정을 구현하고 검증하였다.
